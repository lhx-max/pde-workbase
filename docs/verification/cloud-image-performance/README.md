## 最终行为

- `/raw/` 和 `/files/` 真正处理缩略图与画布预览参数。侧栏为64/320像素cover；画布为128/256/512/1024/2048像素inside，保持全图比例。编辑、下载、导出使用原件。
- `CloudImageFiles.open` 每次先读取真实云端索引，再使用版本绑定的原图或衍生图缓存。项目授权在该步骤之前执行，缓存命中和304都不绕过权限。缓存键包含存储实例、画布、路径、fileId、原图SHA、尺寸和fit，文件版本变化自然失效。未使用本地原件兜底。
- 官方预览接口已实测可用，侧栏缩略优先直接取得其WebP，避免先下载整张PNG。旧部署/大图不支持时才从同一授权原件派生；401/403直接失败，不改走另一取图方式。
- 原件缓存64MB，衍生图缓存32MB；复用已有有界LRU/并发队列（10分钟、最多256条、并发3/2、待处理24）。同图下载和同尺寸转换合并，失败不缓存。缓存是可丢弃的进程内数据，不新增云端表或另一份业务原件；重启后首次取图仍有回源成本。
- 前端继续使用现有渐进解码：考虑画布缩放和屏幕像素密度，保留旧图直到新图就绪；缩放超过2048像素预览需求后取未改动的原图。缩放分档已覆盖4/8倍，避免高倍率仍停留在2倍的预览清晰度。
- 关闭Next开发HMR fetch缓存，避免已改接口仍混用旧PNG响应。官方说明该缓存可以忽略fetch的no-store：https://nextjs.org/docs/app/api-reference/config/next-config-js/serverComponentsHmrCache 。本次出现过“后端直连返回WebP、相同网页URL仍返回旧PNG”，关闭该缓存并自动重载后，相同URL复验全部一致。
