# 资产库调用：独立副本与授权边界

## 正文不共享

- 文档沉淀到资产库时保存的是选定内容的版本快照，不是原 App 文档的活动绑定。
- 每次从资产库导入画布，先在目标工程生成独立文件，再由画布创建新节点；文档 App 安装且可用时，由画布的文档同步流程为新节点建立独立文档身份。
- 内置导入接口不传 `path` 时生成 `asset-<UUID>-<原文件名>`。传入显式 `path` 时仍只允许创建，不覆盖已有文件；重复相同路径返回 409。调用方必须使用返回的 `files[].name`，不能假定目标文件名等于资产版本文件名。
- 外部 HTTP 资产库每次重新读取选定版本并写入独立工程文件；`uses` 仅记录来源，不是复用旧消费者正文或绑定的依据。
- 库内“复制资产”生成新资产 ID，可以复用不可变版本字节的存储；该去重不表示共享可编辑正文。
- 文件发布和画布接收是两个步骤。发布后回执失败会返回部分成功信息，不破坏性撤销文件；画布未接收也不能声称节点或文档已创建。

## 内置库仅限本地单用户

内置库是显式 `dataRoot` 下的一份本地资产库，所有记录的 owner 是 `local-personal`，**没有租户/团队 ACL 或跨团队发布授权模型**。请求必须是 `teamId=local` 且 `userId=local`；其他身份访问内置库返回 403 `ASSET_LIBRARY_LOCAL_ONLY`。

限制覆盖资产库查询、内容、导出、空间、版本、批量操作、工程保存/导入。服务层同样检查请求身份，避免画布 `image.attach` / `image.replace` 绕过资产库路由读取本地资产；此通道返回 403 `CANVAS_ASSET_FORBIDDEN`。

无 HTTP 请求上下文的内部/后台代码，只有通过显式 `dataRoot` 构造的本地服务，仍可执行本地系统任务（初始化、索引、关闭等）。这不是供 HTTP 调用者选择的“系统身份”开关。服务调用的异步上下文保留已验证请求身份；部署宿主必须在路由前用已验证身份替换客户端开发头。开发用 `X-Team-Id` / `X-User-Id` 不是登录凭据，也不能据此宣称服务适合公开多租户部署。

## 跨团队调用需要真实授权的适配器

用户期望的“其他用户调用资产得到自己的新副本”包含两个独立前提：

1. 资产来源确实授权该调用者读取这个版本；
2. 授权通过后，每次调用创建独立副本，不共享原正文。

复制操作不会自动授予源资产权限。需要跨团队共享时，应通过现有 `CanvasServerOptions.assetLibrary.adapter` 配置具有真实源端授权、发布范围与版本读取能力的外部资产库。前端可通过 `configureAssetLibraryAdapter` 接入对应来源。适配器必须自行落实读取/管理授权；来源名称、ID、`kind: external` 和 `uses` 都不是 ACL，简单给本地库换一个 source 名称不会使它成为共享库。

本轮不建立 App 商店、租户资产数据库或通用共享框架。现有资产适配器、App 协议、画布绑定三个边界足够；后续只需在真实共享适配器中补授权，并在各 App 的 copy/create 合同中明确新身份、目标租户归属、不继承源 mirror/binding。
