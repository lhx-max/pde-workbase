# MF 开放 UI 本地集成与验收

## 范围和结论

在独立画布工作区接入真实 MF SDK，不恢复原 bd/Loom 聊天产品、账号平台或聊天数据库。本地画布与资产库仍是本地数据真源。此集成按“先完成本地集成，稍后提供云端配置”实施；**本地测试成功不代表真实 MF 登录、模型执行或云端权限验收成功**。

### 技术边界

| 层 | 实现 |
|---|---|
| 画布包与 Web | 原组件包保留 React／ReactDOM 18.3.1 依赖／类型约束；Next 16.2.6 App Router 自带浏览器渲染器，实测 React DOM `19.3.0-canary-3f0b9e61-20260317`；原组件与资产入口保留 |
| MF 文档 | `@ks-kp/agent-ui@0.1.5-beta.18`、React／ReactDOM 19.2.3、Vite 6；配置可用后才加载完整 SDK |
| 运行环境 | Node 24、pnpm 10.33.2；现有 Electron 宿主不替换 |
| 来源隔离 | 画布 `127.0.0.1`、MF 精确使用保留域名 `mf.localhost`，相同协议／端口、不同 origin；只有一个 Web TCP 监听器，不新增服务器或改 hosts 文件 |
| 通信 | 版本化、源窗口／origin／项目／实例／请求相关性校验的 RPC；超时、取消、去重、防重放与容量限制 |
| 服务端 | 固定 MF 上游、明确 API 白名单、私有服务端认证、HTTP/SSE 与原始 WebSocket 升级代理 |

**安装声明不等于 Next 浏览器渲染器。** [依赖隔离检查](<../e2e/tests/mf-runtime-isolation.test.ts>)验证真实安装的 peer／类型图；[浏览器诊断](<../e2e/lib/playwright/mf-renderers.ts>)通过标准只读 DevTools hook 另行记录实际 DOM 渲染器。实测父文档与 MF 文档各一份，版本如上；未改原画布包的依赖约束，也没有在同一组件树混入 MF。iframe 同时隔离 CSS、SDK 单实例状态和权限，不仅用于处理版本差异。

### 为什么必须是 `mf.localhost`

SDK 在精确的 `localhost`／`127.0.0.1` 主机下进入开发分支，请求 `/sso-health` 并提取 `x-ksap-authn-token`。这不是普通健康检查。使用保留的本地子域名可自然避开该分支，不修改 SDK、不伪造成功、不代理开发 SSO，也不向浏览器返回该令牌。旧 MF 文档域名配置拒绝启用，不能为消掉 404 而增加令牌代理。

MF 的实际本地 Origin 在验证后原样传给上游；缺少 Origin 的浏览器 GET 由受信任的 MF 文档主机确定其真实来源，不伪装为云端域名。认证失效交给 SDK 的公开认证回调处理，禁止默认跳转到登录地址；初始化的晚到 ACK 不能重新覆盖失败状态。执行者选择框表示用户意图，保留切回本地适配器的能力，不把它是否可点当成登录或发送授权。

## 已接入的能力

- 顶部 MF 对话入口、独立可收起／调宽侧栏、项目会话关联、新建／切换会话与状态显示。
- 真实 Chat、输入框、附件上传、模型选择与 SDK 的 SSE／WebSocket 会话链路；不以自制聊天占位框冒充 SDK。
- 授权选区／对象引用、明确选择的文件字节、规范画布修订；不默认发送整个项目。
- 受控 WebMCP：读取上下文与选区、定位、确认后的文本变更、文件导入及绑定任务交付。
- MF 云文件与本地资产区分来源，预览后显式导入真实字节。SDK workspace 预览与 Kim session 文件不是同一下载接口，不能混用。
- MF 与本地 Agent 只能有一个执行者；登记 MF 回执不触发本地适配器。提交前等待规范保存，绑定请求、节点、会话与客户端生命周期；后端再检查输入、修订、取消及目标。

### 原生 API 的闭包

SDK 即使没有排队消息，在流结束后仍会调用原生队列。已核对并开放精确的 POST `/api/kpandora/v1/chat/queue/{list,claim-next,finish,submit,delete,interrupt}`，不是用本地空队列假装成功。活动列表及 CDN／在线文档分页仅开放源代码核对过的只读元数据接口；其请求体、分页、AIE／团队上下文和大小均校验。未知方法、字段、上下文覆盖与任意远程 URL 不透传；云管理、队列管理更新、资产写入等不因某个父路径可用而自动开放。完整接口与限制见 [服务端说明](<../apps/server/README.md>)。

### 必须区分的状态

`初始化配置确认 ≠ 输入框已挂载 ≠ 附件已暂存 ≠ 模型已接收 ≠ 画布已交付`。

普通 Chat 的结束只结束对话流，**不能使画布任务成功**。只有指定交付工具写入成功才完成任务。任务取消防止本地晚到写入，但不保证远端 MF 已停止或停止计费。

## 当前明确限制

1. **画布定向生成只允许新对话。** 当前 SDK 在已有会话发送／恢复时复用客户端 run ID，部分原生快捷发送绕过 `getSendContext`，不能可靠证明本次绑定。已有会话返回 `MF_NEW_SESSION_REQUIRED`，上传与发送前拒绝；不会偷偷新建会话或清空草稿。普通历史对话和暂存不受此限制。
2. SDK 没有可供宿主可靠调用的远程 stop/cancel 接口，也没有统一的最终文件交付回调。远程停止使用 SDK 原生停止按钮；任务交付采用显式工具。
3. MF 文件树未提供公开的只读／隐藏管理菜单能力。工作区／会话文件支持已实现格式的预览与授权导入；CDN／在线文档只开放目录元数据，不获取任意 CDN URL，也不承诺其预览或导入。**不是完整的云文件管理器**；树中可能仍显示不可用管理菜单，界面已有明确提示。普通聊天附件上传是单独的已接入能力。
4. 可选 Office/PDF 云查看器需要额外 worker／WASM／字体运行资产，本轮未部署，明确提示不可用。不影响已有本地 Office 结构化文本预览。
5. 远程部分上传不能声称回滚；未知发送结果不自动重试。运行中的页面／项目切换和旧结果会失效，不能把历史流绑定到新任务。
6. 固定服务端凭据模式只适用于单用户本机环回部署。**不支持共享公网或通过改写 Host／Origin 的反向代理提供多用户访问**。
7. SDK 包体较大：Connected 主 JS 约 8.1 MB，gzip 约 3.2 MB，另有 CSS 与按需资源。未配置时不加载它；仍需后续结合真实网络评估首次启动性能。
8. MF SDK 本身是锁定的 beta 依赖，本地验证不是全平台安全审计或零风险保证。升级后须重新核对 API、组件、生命周期与资源依赖，不能只改版本号。
9. MF 文档的脚本、样式、字体和连接由 CSP 限定，不加载第三方统计脚本或外部字体样式；SSE 与 WebSocket 只连接本地受控代理。依赖外部 CDN 脚本／字体的 MF HTML 预览可能不完整；此策略不改动原画布查看器。图片／媒体另有其格式与来源行为，不把上述限制描述成全类型零外联保证。

## 配置与运行

安装真实 MF SDK 需要访问已配置的企业 npm 源；项目不保存 npm 认证或 MF 凭据。构建及正常启动命令见 [主说明](<../README.md>)；服务端配置、CLI/API、文件权限及来源规则见 [服务端说明](<../apps/server/README.md>)；SDK 层详细限制见 [MF 文档说明](<../apps/mf-ui/README.md>)。

需要提供：

- `CANVAS_MF_UPSTREAM_URL`：获准使用的 MF HTTPS 服务地址。
- `CANVAS_MF_AIE_USERNAME`：实际获准的 Agent/AIE 用户名。
- `CANVAS_MF_COOKIE_FILE` 或 `CANVAS_MF_AUTH_TOKEN`：二选一的服务端认证；Cookie 文件必须为受保护的绝对路径，不入 Git，不放进项目文件。token 采用 `Authorization: Bearer`，只适用于明确支持该认证方式的目标网关，不能把 SDK 开发 SSO 令牌随意当成 Bearer。
- 可选 `CANVAS_MF_WORKBENCH_ID`、`CANVAS_MF_TEAM_ID`。团队文件导入限制在声明的团队范围。

启动器负责 MF 文档 URL 与静态目录，不在浏览器、iframe URL、桥消息或画布 JSON 中传递认证凭据。更新认证后重新加载项目文档；不要将原始凭据发送给模型。

MF 会话、导入、任务登记与交付也可以通过同一套后端 HTTP/CLI 调用。**登记 MF 任务不等于从 CLI 启动 SDK 生成**；浏览器侧实际执行与可信交付链路不能被登记命令冒充。

- [Web 边界回归](<../apps/web/tests/mf-server-boundary.test.ts>)覆盖独立静态文档、CSP、路径／符号链接、Host／Origin／转发头和凭据注入边界。

五个正常流程的 HTTP 失败列表均为空；全部六个场景没有 `/sso-health` 请求。认证场景仅出现主动注入的预期 401，业务码 40101 的实际登录跳转字段亦经过 SDK，但公开认证回调阻止导航，宿主保持失败／不可发送状态。没有未捕获页面异常。CSP 拦截的第三方统计脚本、日志连接、外部字体及其控制台记录完整保留，**不声称控制台无任何输出**。

最终目视复核还发现宿主的全局 `button` 样式把 SDK 原生预览工具栏图标压成 0px 宽。浏览器红测复现后，按钮样式改为仅作用于宿主专属类，不修改 SDK、字体或 CSP。最终三个不同原生图标均实测为 **16×16px**、按钮 **20×20px**、横向 padding 为 0；原图与几何记录同时保留，不能仅凭导入状态正确就判定视觉完整。

旧轮次记录仍保留：错误的团队 fixture 被权限规则拒绝；真实浏览器发现并修复了导入回执丢失摘要、原生队列路由缺失、布局、初始化 ACK 语义与认证竞态。旧 `/sso-health` 404 被审计为开发令牌分支后，以保留域名修正，而非伪造健康或登录结果。测试数量不是代码覆盖率或零风险声明。

## 后续云端验收清单

提供授权配置后，按下面顺序验收，失败时保持明确不可用，不打开宽泛代理作为临时修复：

- [ ] 实际 Cookie/token 身份、过期／续期提示与服务端文件权限。
- [ ] MF Gateway 允许真实本地 frame Origin；不伪造为云端 Origin。
- [ ] 实际 AIE、模型目录、计费权限与正常流式生成。
- [ ] SSE 与 WebSocket 建立、断线恢复、会话历史与原生停止语义。
- [ ] WebMCP 注册／更新、人工确认、文本交付；不是仅看到工具列表。
- [ ] workspace 与 session 文件的实际权限、团队限制、字节／摘要及显式导入。
- [ ] HTML／演示产物、已有编辑／引用变化、取消和迟到交付。
- [ ] 真实数据量下的启动、附件大小、回执恢复与错误提示。

未配置服务、模型回覆结束、伪造工具响应或仅成功编译，都不能替代这些云端验收。
