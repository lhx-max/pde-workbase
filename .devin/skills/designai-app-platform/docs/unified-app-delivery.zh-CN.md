# DesignAI App 可靠性与统一交付合同

版本：3.2.0；修订日期：2026-10-23。适用于具有对应能力的独立App、宿主适配器和共享后端工具。条款源于画布、文档、草图、生图联调；新App按能力适用，不要求复制其业务算法。架构与流程见白皮书，精确API见app-development-spec.zh-CN.md；实现/发布/运行状态查各App执行证据，不从规范推断已部署。

## 身份与资源归属

MA 验证当前用户及应用实例后，App 才使用身份。客户端 actor、自报租户、菜单是否可见都不授予权限；当前动作授权要在服务端单独检查。App 不维护第二套 MA 组织、项目或角色目录。

资源同时约束 teamId、bizId 和实际创建时的应用/实例/Provider 归属。文档、草图把必要业务映射保存为 maApplicationId、maApplicationInstanceId、maProviderInstanceId；它们只由可信 TenantContext 派生，不能直接复制请求体。缺完整映射的旧资源不自动认领。不同用户被 MA 授权访问同一实例时可以协作，不把 createdBy 当作读锁。不同 MA 实例即使同租户、同业务、同用户也不互相开放资源。跨 App 改绑需要宿主明确的授权/交接合同。

回执缓存、持久 reservation、串行锁和恢复键的作用域包含完整 MA 元组、调用人、操作目标与原请求键。查回执及重放前重新检查当前身份、资源及动作权限；撤权优先于历史成功。长连接不能永远沿用建立连接时的权限。

## 版本与不确定结果

Provider 外层 revision 是正的安全整数，但必须作为不透明基线使用，不假设每次恰好加 1；画布投影自己的核心版本，文档/草图保存自己的逻辑计数器。正文/场景内容哈希是内层基线。写入带最近实际读取的外层版本及对应内层基线，不能临写前读最新内容替用户盲覆盖旧稿。

一次逻辑变更的请求键、正文、身份作用域和版本固定。响应丢失后保留原请求，显式重放/查询/确认；单纯读到当前状态不能清除待恢复记录。客户端重渲染不得重置草稿。认证/Provider工厂接收白名单字段构成的不可变身份快照，不能捕获宿主可变context引用；A→B切换后的旧transport、保存回调和flush回调不得借用B的凭据或操作B。只忽略迟到响应不足以保证请求没有发错；验收还要原地修改同一context对象、替换嵌套actor并触发旧回调，核对实际请求作用域。不要自动重跑生图等有成本操作。

未确认写入由用户显式重放或核对确认后，编辑器必须同步恢复状态与可编辑性：清除失效错误、更新已保存基线，并验证下一次自动保存可用。只有恢复记录已解决且当前草稿与规范内容一致时，才能将其标为已保存；读到云端内容本身不解决未确认写入，云端旧内容也不得覆盖恢复期间的新草稿。验收覆盖提交成功但响应丢失、原键重放仅一次业务变更、后续编辑、刷新与新草稿保留。

MA Provider 的业务实例标识不等于本地 projectId。画布通过已认证 canvas.read 返回的 canvasInstanceId 打开已有实例，挂载不创建。新画布映射使用 35 字符 ID 以满足云存储 documentId 限制；完整元组仍存储并校验，旧本地长 ID 仅按已有合法映射兼容。

## 归档、恢复与定位

资源权属元组、MA Provider 的规范绑定与画布卡片/镜像绑定是三种职责，不能因复用一个存储字段而合并生命周期。解除画布绑定不代表撤销原 MA Provider 的业务定位；复制产生独立资源，也不能按“同一权属元组的首条资源”重算规范目标。归档后的列表发现、已知业务ID审读、Provider定位、文件读取、写入和恢复分别按App合同声明，不能从一个入口推导所有入口。既有合同允许的授权审读保持完整作用域校验；原本只查活动绑定的Provider入口，仅为归档回放/显式恢复增加受完整权限和版本校验的归档定位，不以开放所有读写修复恢复。

归档原键回放、恢复原键回放必须定位原业务目标并返回既有结果，不依赖只包含活动资源的列表。恢复后核对同 Provider、同业务 ID、规范字节与权限仍一致；重复恢复活动实例不得重置无关关联或制造版本变更。跨重启复验此链路，同时验证副本不改源内容、普通卡片恢复不重新绑定已失效镜像、外部实例不能恢复或读取回执。

## 云权威与运行交付

业务头、文件字节、绑定、回执/恢复意图及治理记录使用对应云存储；本地 SQLite/目录只做可丢弃投影或显式隔离测试，不能备份整目录再称全部上云。多持久化目标间不宣称原子性；先保存规范字节，再确认元数据，失败必须明确返回。

持久状态DTO在写入前经过实际JSON codec校验：可选字段显式省略或按领域schema归一，undefined、非有限数、循环引用和未转换的Date/Map/BigInt等不得直接入库。不能用只支持内存Map的替身证明真实序列化可用；至少以实际codec完成写入、flush和新实例读回，覆盖manifest等可选字段。

flush或提交失败后，不得继续把未确认的内存状态当已保存数据返回或静默自动重试。受影响的写通道进入明确不可用/待恢复状态，保留原请求及已知回执；按已声明恢复流程核对云端结果再恢复服务，不换新键重跑。跨多个持久化目标的部分成功也须单独报告。

无 CAS 的 Appwrite 服务遵守实际独占 writer lock 和单副本部署，正常关闭先停请求、刷数据再释放自身锁；崩溃锁不按时间自动抢占。验收关闭阶段另查进程退出码和最终写锁：容器 removed、启动健康或中途一次锁释放均不证明最后一轮已安全关闭。强制退出、未确认 flush 或残留锁必须报告失败；先核对原写者及规范数据，再由获准运维按明确流程恢复，不自动按时间抢锁。生产启动只读核验私有 collection/bucket ACL。新建文件显式收窄并确认自己的 grants，冲突对象不自动修复；旧开发 bucket 的 users-read 不是生产租户隔离。平台 signature 按不透明值处理，字节完整性由自己的 SHA256 验证。

关闭时分别处理网络连接与业务操作：未进入业务处理的空闲连接不能无限阻止退出；已接受的异步操作即使客户端断开也必须继续纳入排空，待其确定结束后才能刷状态、释放写锁。停止接收新业务后明确返回暂不可用；不得以强制断开全部连接或直接释放锁代替安全关闭。验收包含空闲预连接、执行中的写入、客户端中断和完整页面操作后仍有轮询的退出场景。

回执与恢复账本的容量必须按真实存储限制设计，分别验证单条大结果和长期累计数据。不能把所有有键回执无限追加到一个有固定大小限制的状态槽，也不能以静默淘汰历史键解决容量问题。分片存储需先确认内容完整，再发布可读取的索引；部分写入不得成为成功回执。改变持久格式时声明升级、崩溃恢复和旧版本回滚边界，保留已确认与不确定记录，校验缺片、摘要和作用域；通过真实序列化及重启读回验收。

本批四 App 的完整后台交付以各仓发布清单中的 Node 服务和容器为准，不把某个旧的部分 Function 入口当作完整后台。新 App 可选择合同明确且实际验收的部署形态，不能把这一实现快照推广为所有 App 必须同一进程或 Dockerfile。生产运行身份、HTTPS 网关与资源鉴权通道须实际提供并验。维护 Cookie/Session 仅限明确开发检查，不能用于共享生产；模型用户凭据和 MA SSO 也不是同一凭据。

携带存储服务凭据的HTTP客户端固定可信目标；本批使用redirect:error，其他适配若支持跳转须有等价的逐跳授权校验，不能向重定向目标自动转送凭据。上游原始错误body可能含内部信息，不透传到UI/CLI/回执；保留可诊断状态、稳定错误码和请求关联即可。

产物 manifest 与相同规范字节的 SHA256 绑定；占位符/退化守卫在发布前执行。云端文件列表、预览和 ZIP 不能落回旧本地目录。未实现的高级能力明确 unavailable，不让请求掉进旧文件路由后假成功。

## 包与外部接入

本地vendor/tgz也必须按字节定位。候选包重打后若内容变化，使用新版本或带内容哈希的新路径，并同步消费方声明与lockfile；已发布版本不可原地替换。不能只清本机缓存或放宽integrity来掩盖旧锁引用。先固定最终制品/SHA，再从这些字节完成冻结锁的干净安装、类型/CSS/Node出口验证；制品变化后旧消费者报告不再证明新包。

嵌入包装层负责其内部布局，宿主提供明确可用尺寸。不能依赖独立壳的私有样式使编辑器获得高度；使用已安装制品在只有公开 CSS 的消费页验证工具栏、可见内容和交互区域。Canvas 等绘制节点须测量实际非零尺寸，并在保存后刷新核对渲染内容，构建成功或后端已有元素不能替代可见性验收。

App 提供独立 surface、纯 Provider 传输和自有 MA 包装层；复用既有 UI。目标宿主真实传 context/fileClient/conversation，不能依赖可选 providerClient 必定存在。应用部署入口配置逐请求凭据 getter、受认证的图片/frame 资源桥、可用的导出/对话桥；缺桥不扫描浏览器存储、不往 URL 塞 MA 票据，也不修改对方 SDK、菜单或 Agent 调度。

[Plugin Kit App 示范仓](da-plugin-kit-integration.zh-CN.md)展示 SDK/静态 registry/Preview；示范合同与本项目云存储/持久恢复要求分层记录，yihan-dev-ma 是另一个仓库里的 MA 后端/测试宿主分支。包安装与构建、真实云数据、自有合同 fixture、正式 MA 登记/同实例读回/撤权、真实 Agent、staging 六类证据分开报告。MA Provider 的 action结果、snapshot以及调用者→MA请求分别使用各自信封，COI格式不直接复用。新 App 在编码前把这些接缝写进 APP_CONTRACT，后续只执行当前 profile 适用门，不把外部条件未齐当成本地造成功的理由。

## 后端专项验收补充

适用于具有对应能力的App，不要求所有App实现相同业务算法。完整规则见白皮书“后端必须形成的闭环”，本节规定联调时必须落实的边界。

- 缺少biz或其他必需归属字段不视为通配；正文、metadata、文件、回执、缓存、锁及后台投递使用一致作用域。显式null/数组等非法input在解析期拒绝，不留副作用。
- 所有持久化mutation均受相同可信写授权和并发前提约束，包括rename/archive/bind、后台投递；只在正文PUT加单写者检查不构成闭环。
- 新环境从实际schema预置开始验收：字段类型/长度/必填性、MA归属字段、索引、运行锁集合、ACL及异步创建完成状态。不能把旧库可用推导为部署脚本正确。
- 读取语义按精确动作/路由授权；媒体wait即使使用POST仍可属于读权限，取消/重试仍是写。不得用宽泛HTTP方法或路径后缀替代动作审查。
- 回执声明保留范围/期限和过期行为。无键临时缓存可以有界淘汰；有键幂等声明不得静默丢弃后按新写入执行。具体上限与期限由App合同决定，不强制复制某个App的64条实现。
- 真正的鼠标、键盘和状态读回可用于复核自动化异常；单次语义点击无效不足以证明产品缺陷，未经复现不修改交互实现。

## 异步请求与任务的最小语义合同

以下是语义要求，不新增一套通用HTTP API。各App在合同中将实际字段映射到这些含义，继续使用自身已发布schema。

| 概念 | 必须明确的语义 | 当前媒体链路示例 |
| --- | --- | --- |
| 逻辑操作身份 | 同一用户意图的稳定键、输入、授权作用域和提交基线；一对多输出返回固定任务集合 | idempotencyKey/clientRequestId → receipt → taskIds |
| 任务身份与状态 | ID作用域、持久化位置、可观察状态及终态定义；前后端别名有明确映射 | queued/running/done/failed/interrupted，不直接混用UI completed |
| 目标条件 | 原实例/节点/资产、内容版本或替换标记、原路径；与全局布局revision的关系 | canvasDelivery的nodeId/basePath/baseVersion；不因无关拖动盲目改写目标 |
| 投递与资源 | 规范路径、产物字节/哈希/类型、索引和回填确认分开；展示桥URL不作为规范交付地址 | 规范项目文件标识 → 服务端交付 → 浏览器资源桥 |
| 重放与重试 | 同键重放返回原任务集合，包括失败/取消后；新的执行意图显式使用新操作身份 | 响应丢失不换键，不自动再次付费调用 |
| 取消 | 本地请求、执行器abort、供应商取消、账单处理分别可观察；已完成产物的保留规则 | interrupted/failed的映射和源卡busy释放分别读回 |
| 条件回填 | 目标删除/替换、权限撤销、过期结果不覆盖新内容；产物保留或回收有规则 | 迟到结果记录冲突，规范文件可保留而不回填 |
| 恢复 | 原请求/outbox与任务/投递回执重建；凭据只在当前受信任调用中获取 | 重启不改旧请求摘要，不凭“不见任务”自动重新生成 |

没有真实供应商取消/退费证据时仅报告受控执行器取消通过。没有持久队列时明确不可重试；未配置镜像或绑定返回unbound/unavailable，不以正文保存成功推导跨App同步成功。

## 持续规范维护

资源审批按 [仓库与资源目录](platform-resource-catalog.zh-CN.md) 的负责人归属。每次涉及身份、持久化、协议、资源或制品边界的变更，交付中附规范影响判断并更新对应合同/模板/目录；仅实现偏离既有合同的修复可记录案例与回归，不重复增加全局规则。按白皮书维护流程保留兼容和证据。
