# DesignAI App 规范审查与修订记录

版本：3.2.0；审查日期：2026-10-23。范围为现有规范、App 合同模板、相关本地 schema/能力清单以及 PDE Agent 1.0.7 内置资料。没有重跑四 App 功能、正式 MA 注册或线上发布验收。

## 1. 总体判断

按业务 App 管权威数据、画布组织卡片、DA/MA 管宿主身份和目录、公开协议连接能力的方向合理。主要问题是早期画布视角与后续通用规则混写、已废弃动作名残留，以及工具默认值缺少适用范围；不能只靠改技能名称解决。

入口和分发名称统一为 `designai-app-platform`。所有 App 的共同要求保留在白皮书；Canvas COI、卡包、正文同步和外部 MA 的专属规则按能力/profile 加载。PDE 作为内置工具资料，通过适配层采用。

## 2. 本次修正

| 问题与依据 | 修正 | 适用范围 |
| --- | --- | --- |
| 名称仍是 canvas，容易误解只服务画布 | 更名、更新入口和分发结构，保留旧包作为历史版本 | 整套规范 |
| API 规范仍写“生图当前复用画布后端” | 现行目标为独立生图后端与私有资源；旧共享实现仅作兼容 profile | 生图与画布边界 |
| 白皮书的原子发布表述覆盖跨服务，与 outbox 部分成功相冲突 | 原子承诺限定在实际事务边界，跨系统分阶段确认、条件发布并恢复对账 | 异步/跨 App 交付 |
| `platform` 目录可见、entitlement check 容易被理解为业务授权 | 明确显隐不授予业务权限，所有入口仍检查可信身份、实例与动作 | Canvas COI / MA 授权 |
| 卡包文档首行损坏，动作名仍有 node.patch / canvas.undo / layout.auto | 修正标题，按本地 schema 使用 node.rename / layout.arrange / operation.undo 等；onPatch 是 UI 回调 | 卡包与公开动作 |
| 互联协议把 node.update 描述成任意标题/文件路径补丁 | 按真实卡种 schema 选择动作；文件/产物切换使用专属动作 | 画布操作 |
| 互联协议写三个通道但实际列四个，非草图内容一概归共享桶 | 修正通道数，区分轻量 JSON、画布工程镜像和 App 自有正文/产物 | 卡片与 App 互联 |
| 冲突后“读最新再改”可能诱导盲覆盖 | 保留原意图/基线/草稿，按领域冲突策略或用户确认处理；结果不确定保留原键 | 并发与恢复 |
| 文档 create、usage、归档字段和画布工具链可能泛化成所有 App 必需项 | 标明 COI 文档适配词表、按消费合同选择用量接口/生命周期，目标仓登记自己的工具链 | 新 App 开发 |
| 早期云表写“编号由基座直接传入”、回执仍为内存、治理全自管 | 改为可信映射解析，回执按现行合同持久化；MA 正式目录不由业务 App 另建 | 数据模型 |
| “本地跨源可放开”与实际身份授权边界不清 | 明确精确来源/凭据配置，同源代理可免 CORS，CORS 不代替鉴权 | 网络与认证 |
| PDE 原入口引用 appwrite-cf.md，但快照实际是 appwrite-cf/SKILL.md | 内置完整资料并修复本地路径；嵌套 Skill 改为资料入口，防止被当成独立规则覆盖总入口 | Skill 可移植性 |
| PDE 脚手架、依赖升级、前端 SDK、登录和静态部署默认值与既有 App 冲突 | 新增采用矩阵，保留现有技术栈和后端权威；静态发布不等于后台或 MA 注册 | 工具集成 |
| 协议字段速记被标成 JSON，带注释的例子也标为可直接提交 JSON | 字段速记改为 text，注释示例改为 jsonc；请求须填实际值并经 schema 校验 | 示例准确性 |
| PDE 说明将包名与实际连接目标直接等同 | 区分内部工具支持政策与 endpoint 配置事实；内置副本纠正此解释并记录适配 | 工具资料准确性 |

动作核对来自画布仓 `packages/contracts/src/api/canvas-operations.ts`、`canvas-relations-layout.ts`、`apps/server/src/canvas-manifest.ts`、卡注册与公开 props。字段/动作存在只证明源码形状，不代替业务运行通过。

## 3. 保留的原则与不作的扩张

保留可信身份与完整资源作用域、私有云存储、条件写与幂等、真实制品安装、重启读回和分阶段验收。没有新增统一业务数据库、第二套组织/角色目录、虚构正式登记 API 或要求每个 App 复制全部 P1–P24。

PDE 的网站设计、OneSQL、运维资料按任务读取。完整内置不代表每次开发必须执行所有模块，也不代表获取了私有数据权限。历史审计、旧端口、测试数量、SDK 快照和开发 ACL 均保留日期，不能作为新环境配置。

## 4. 仍需外部核对的事项

目标基座正式登记机制、版本/ID 签发、真实身份委托与动作授权、HTTPS/资源桥、Agent 执行环境的工具发现和网络能力，仍按 App 合同向对应负责人取得。PDE CLI/SDK 的目标环境版本与命令能力在实际使用时验证。本次文档审查不把这些缺口改为已通过。

分发验证应包含标准 Skill frontmatter、全部资料可发现、包内文件/标题引用、PDE 相对路径、指纹完整性、独立目录解压以及缺文件/篡改/越界引用拒绝。三种任务走读为纯 JSON 卡包、新独立业务 App、已有 App 接 MA：分别确认读取的合同、交付物和 N/A 边界；未进行实际新 App 开发或模型盲测，不据此承诺零上下文必然完成所有外部接入。
