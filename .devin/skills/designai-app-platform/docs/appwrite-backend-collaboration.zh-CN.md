# Appwrite 后端授权：添加成员与权限排查

核验日期：2026-10-26。适用于公司内部 Appwrite 的开发维护协作。检索关键词：Appwrite 后端权限、给同事开权限、添加用户、添加成员、Add Member、找不到按钮、组织首页、完整管理权限、数据库权限、云函数部署权限、桶只读。

## 快速解决

**让同事维护 Appwrite 后端：打开 [Appwrite Console](https://frontend-cloud.corp.kuaishou.com/console)，回到目标项目所属的组织首页，由组织 Owner 点击右上角“添加成员”。**

“添加成员”与组织名称标题处在同一行。项目、数据库、云函数和桶详情页通常没有这个组织成员按钮；在这些页面找不到时，先通过左上角组织名称或 Appwrite 标志返回组织首页。界面语言不同可能显示 `Add Member`。

不要把某位维护者的组织名称、组织 ID 或个人 Console 深链接写成所有人的固定入口。每位操作者应进入目标资源实际所属组织；组织地址形如 `/console/organization-<organizationId>`，路径中的 ID 不是 Appwrite projectId，也不是 MA 的 applicationId。

官方依据：[PDE FAQ：如何让同事拥有项目的修改权限](https://pde-agent.frontend-cloud.corp.kuaishou.com/faq/69f1b7390012fc33e6e8)。FAQ 分别给出了前端站点协作入口和 Appwrite 后端成员入口；本次已实际进入 Console 核对组织 Owner、“添加成员”及邀请表单，不是只依据 FAQ 推测按钮存在。

## 授权步骤

1. 确认目标 Appwrite projectId，并在 Console 核对所属组织及当前操作者角色；由有成员管理权限的组织维护者执行。
2. 进入组织首页，核对其中列出的所有项目。当前入口是组织级，不能当成仅授权一个桶或四个 App；项目内其他业务资源也须纳入影响判断。
3. 点击“添加成员”，填写同事的公司邮箱前缀并确认。2026-10-26 表单支持回车、空格或逗号确认多个前缀；默认角色为 `developer`。
4. 核对人员、角色、授权范围和任务需要后提交。默认 `developer` 不是已实测具备所有管理能力的证明；不为省事自动授予 Owner，不将邀请成员变成转让所有权。
5. 成员添加后，由接收方用自己的正常登录态核对成员身份及所需能力；保留脱敏结果与撤销方式。不能用原维护者账号的成功结果代替接收方验收。

若组织级范围超过本次授权边界，先由资源所有者确定合适的组织/项目隔离或代维护方式；不通过公开数据库、桶或共享管理凭证绕过。

## 各类权限不能互相代替

| 要完成的动作 | 对应入口或合同 | 不代表什么 |
| --- | --- | --- |
| 共同上传、修改静态前端站点 | 站点详情的“协作成员” | 不证明已取得 Appwrite 后端维护权 |
| 修改数据库 schema、维护存储、修改/部署云函数 | Appwrite Console 组织成员及实际角色 | 不自动获得 MA 应用目录登记或业务用户权限 |
| 下载或修改某个文件、读写业务数据 | Appwrite 桶/文件、集合/记录 ACL 或受鉴权的业务 API | 不授予云函数代码与部署管理权 |
| 调用某个云函数入口 | Function execute 权限及函数内部鉴权 | 不授予修改函数和部署的权限 |
| 正式注册 App、创建实例、授予业务动作 | 宿主 MA 的正式目录/实例/动作授权合同 | 不等于加入我方 Appwrite 组织 |
| CLI 登录成功或安装 npm 组件 | 本人登录、组件安装 | 不证明上述资源或业务动作已获授权 |

## 按症状查找

| 问题或返回 | 首先怎么处理 |
| --- | --- |
| 找不到“添加用户 / 添加成员 / Add Member” | 确认位于 `/console` 的组织首页，而非 `/web-artifacts`、项目或桶详情；核对当前组织与角色 |
| 只看到“转让管理员” | 先确认是否误入静态站点成员页；不要把转让站点管理员当作新增 Appwrite 后端维护者 |
| CLI `projects get` 返回 `Access to this API is forbidden` | 仅记录该 CLI 路径被拒绝，继续检查正式 Console 成员入口；不能据此认定平台不支持后端共享 |
| CLI 报 `Do not know how to serialize a BigInt` | 归类为工具序列化错误；不是已证明的资源授权拒绝，也不是后端业务成功 |
| 已加成员但部分操作仍被拒绝 | 用接收方本人身份检查组织、角色、projectId、具体接口与所需操作；区分成员管理权、资源 ACL、Function execute 与业务鉴权 |
| 想直接公开桶来解决维护权限 | 桶公开读取不能授予数据库 schema 或函数部署权限，应回到 Console 后端成员授权 |
| App 返回 `CLOUD_STORAGE_NOT_PRIVATE` | 检查实际集合/桶 ACL 和 per-item security；这是当前 App 存储预检合同，不能只改公开 ACL 就宣布接通 |

## 只读共享与后端维护分开

若需求只是让指定人查看文件，可采用明确的文件读取授权或受鉴权的业务读取入口，无需为了下载文件授予后端管理员。

2026-10-26 隔离云端实测：桶 ACL 为空且 `fileSecurity=true`，文件仅授予指定账号 `read` 时，该账号能下载并得到一致字节；匿名和另一普通账号无法读取；指定读者、其他账号和匿名的上传、改名、扩权与删除均被拒绝。当前共享私有存储预检接受这种文件级读取授权，但会拒绝桶级公共或指定用户 `read`。

该结果仅适用于满足前述配置的资源。旧开发桶可能已有广泛读取授权或 `fileSecurity=false`，不能直接套用文件级授权并宣称完成隔离。既有文件授权也不会自动传播给未来的新文件；持续共享、撤销、文件替换和版本更新必须另行实现与验收。四 App 原业务桶本次未公开。

## 验收出口

邀请成功只完成成员添加。需要后端维护的接收方应在明确的隔离资源中实际验证：

- 能读取目标数据库/集合与桶元数据，不能把资源不存在、CLI 错误和授权拒绝混为一类。
- 能完成授权范围内的测试记录、测试文件写入/修改并独立读回，文件字节可核对。
- 能在专用测试 Function 修改非敏感配置、提交部署、读取部署终态并执行验证，不覆盖正式函数做权限试验。
- 能验证职责之外的访问限制及撤权结果；测试账号、会话、文件和临时资源按预先声明的方式回收。

回传账号角色、组织/项目范围、资源标识、时间、操作及脱敏返回；不回传 Cookie、Token、密码、API Key 或原维护者的 CLI 认证目录。本文提供正式入口和检验方法，不证明任何指定人员已经被添加或已取得全部后端能力。
