# 图片 App 接入案例：故障、处理与验收

2026-10-21整理。适用于嵌入组件、资源预览、异步媒体任务和 CLI 接入；以下是图片开发中的实际案例，不要求所有 App 复制图片字段、缓存参数或数据库结构。

先读 [开发手册](app-development-handbook.zh-CN.md)。本文补充现有规范没有展开的故障处理，不另建动作协议；图片精确调用格式见 [图片 CLI 合同](../../../../docs/image-cli-contract.zh-CN.md)。证据是当次观测，复用前检查当前版本与运行环境。

## 案例1：独立组件已挂载，详情业务尚未完成

**现场**：图片菜单和卡片可见，用户自然会追问“图片 App 是否已注册、后端是否全部独立”。本地又有图片测试页，容易把独立测试壳误当成完整画布接入。

**处理与判断**：

- 分别检查：卡包 `/server` 元数据、`/react` 实际 renderer、业务 App manifest/endpoint、详情模式回调。菜单可见只证明其中一部分。
- 使用真实 tarball 在完整画布内加载 `ImageCanvasCard` / `ImageModeEntry`，不是复制组件源码到画布或只展示独立测试页。服务端出口保持无 React 依赖。
- 本轮 `image` 动作采用显式的画布图片工作区 profile：instanceId等于canvasId，input.nodeId指卡片；存储/执行器由宿主注入。不能据此宣称独立图片业务数据库和详情模式已完成。
- “进入图片模式”先保存，再交付画布ID、卡片ID、路径和画布版本。未接详情入口明确不可用，不创建空详情页或假业务实例。
- 纯云端界面去掉 Finder 类入口。尚未打通的卡片“上传图片”和“模板”快捷入口按用户要求隐藏，不把其他上传入口一并删除。

**验收**：安装产物在完整画布渲染、刷新仍能读回；详情未接/权限不足/保存失败时保留原图；正式详情接入后再验证真实同图打开及结果回传。

**证据**：[打开合同与责任](../../../../docs/image-app-handoff.zh-CN.md)、[完整画布组件与打开事件](../../../../docs/verification/image-app-handoff/README.md)。历史截图的包版本不代表今天安装的版本。

## 案例2：占位卡显示“生成中”，后端根本没有该任务

**现场**：提示词“一只狗”，卡片长期转圈；浏览器草稿有预测taskId，后端查不到任务，保存返回409。

**已确认原因**：前端先添加 active task/queued 占位，再 flush 画布。flush冲突后模型提交没有发生，预测状态却没有撤销。它不是模型耗时，也不证明供应商已扣费。

**处理**：

1. 先保存既有修改；保存失败不创建任务目标。
2. 准备任务目标/占位并保存；这一步失败，撤销本次预测任务与未完成占位，再向用户报告保存错误。
3. 目标保存成功才允许调用执行器。已经受理的真实任务不能套用“提交前回滚”逻辑；保留taskId和产物，走取消或交付恢复。
4. 对历史“生成中”状态按taskId查后端/云端证据。找不到且前置保存失败时释放busy并保留草稿，不能一直轮询不存在的任务，更不能换key再次付费生成。
5. 浏览器草稿与云端布局冲突时，两份先备份；用户本次明确选择只保留“一只狗”的布局后才条件写恢复。这个选择不是以后自动覆盖云端的通用授权。

**验收**：[三个回归测试](../../../../packages/canvas-workbench/tests/image-submission-persistence.test.ts)覆盖保存前失败不prepare、prepare后保存失败rollback、成功顺序为save→prepare→save→dispatch。实际恢复与上游任务证据见 [无限等待诊断记录](../../../../docs/verification/cloud-image-performance/README.md)。

## 案例3：CLI已报告成功，画布仍没拿到图片

**现场**：真实GPT任务约51秒完成，模型状态done，验收立即查画布却没有ready输出。

**已确认原因**：回执只看模型终态，后端云端回填仍pending。任务完成与交付提交存在时间差。

**处理**：将任务执行和画布交付分别记录。模型done但delivery pending仍返回accepted；确认回填提交完成后才succeeded。交付失败明确失败并保留原产物，不通过重新生图“修复”交付失败。多张逐项保留taskId及结果；部分受理不能伪装成付费请求可原子撤销。

**验收**：真实任务回执、画布ready节点、云端文件下载与实际尺寸一致；新增测试强制done+delivery pending，断言不会提前成功。见 [image-app集成测试](../../../../apps/server/tests/image-app.test.ts) 和 [CLI真实云端证据](../../../../docs/verification/image-cli-20261021/README.md)。该次图片2048×1536，恢复验收复用原key，没有新增付费请求。

## 案例4：整个画布灰屏，不能把加载失败当成空画布

**现场**：页面只有空工作区容器，云端实际仍有图片/草图，首次状态读取未完成。

**确认范围**：确认首次读取卡住；没有取得它在网络层停滞的最终原因，不能把网络猜测写成根因。

**处理**：首读提供loading、有限超时和可重试错误（本轮15秒）；失败时不挂载依赖默认空状态的消费者，避免空值被保存回云端。稳定默认配置数组，避免宿主无关重绘重复触发读取。恢复/切换仍使用当前实例和版本，保留未提交草稿。

**验收**：[首读回归](../../../../packages/canvas-workbench/tests/canvas-initial-load.test.ts)验证超时/离线不挂默认内容、不产生写请求，重试能读回已保存状态；实际画布恢复截图见 [性能与恢复记录](../../../../docs/verification/cloud-image-performance/README.md)。不要通过重建空画布或清掉用户数据来消除灰屏。

## 案例5：叫“缩略图”的接口实际传了几MB原图

**现场**：资源缩略图和画布加载慢，某1024预览请求实际返回约6.2MB PNG；后端直连接口已返回WebP，但Web代理同URL仍给旧PNG。

**处理**：

- 分别量测权威存储→后端→Web代理→页面的Content-Type、实际字节、尺寸、耗时。URL含width不证明服务实际缩图。
- 原件保持不变；资源侧小缩略图、画布按显示像素选择预览，大倍率及编辑/下载/导出按需取原件。用户能看高清不意味着所有列表都先下载原件。
- 本轮侧栏64/320、画布128–2048分档，并结合缩放和DPR；切高清前保留旧图，避免闪空。分档是本轮策略，不是新App必须照抄的固定尺寸。
- 官方预览能力可用时优先用；当前公司端点已实测支持预览，但没有CDN节点/命中证据，不能把“使用Appwrite”当作“已使用官方Cloud CDN”。
- 本轮发现Next开发HMR fetch缓存给旧响应，针对开发缓存配置修正并沿Web入口复验；不要为此关闭生产缓存或鉴权。

**安全与存储**：每次先验证项目授权与真实索引；缓存键隔离存储实例/画布/路径/文件身份和版本/转换参数，缓存命中或304也不绕权限。401/403直接失败，不改走备用取图通道。衍生图/缓存可丢弃，不形成第二份权威原件；冷启动仍有回源成本。浏览器/服务间传输出现base64不等于云端数据库以base64保存图片，按实际Storage文件与索引分别查证。

**验收**：比较真实Web入口冷/热请求、并发去重、错误授权、原件字节不变、版本替换失效。该次1024预览17,144B WebP，但不能从本机热缓存数字推导线上SLA。完整高倍率手势视觉复验当次未完成。证据与缓存限额见 [性能记录](../../../../docs/verification/cloud-image-performance/README.md)、[云端文件测试](../../../../apps/server/tests/cloud-image-files.test.ts)。

## 案例6：资源缩略图灰，画布图片却能打开

**现场**：视野内图片请求迟迟未完成；画布变换/滚动容器中，文档级lazy判断不适合当前节点可见性。

**处理**：画布使用已有视口邻近度，视野附近的图开始加载，屏外仍懒加载；侧栏用自己的IntersectionObserver，接近可见区才挂载图片。不是把整个项目的所有原图改成eager。缩略图失败要有可重试/错误状态，不能让灰色占位代表成功。

**验收**：页面实际图片complete且naturalWidth>0，同时肉眼确认内容；资源引用计数、预览、拖入画布和刷新读回分别核对，截图有图不证明拖拽已通过。该次恢复4/4图片；见 [视口预览测试](../../../../packages/canvas-workbench/tests/image-preview-policy.test.ts)、[侧栏缩略图测试](../../../../apps/web/tests/canvas-resource-thumbnail.test.tsx) 与 [恢复截图记录](../../../../docs/verification/cloud-image-performance/README.md)。

## 案例7：HTTP200 / success=false / code601，不能假定授权过期

**现场**：Gemini返回HTTP200，但业务success=false、code601、“未找到相关内容”，没有图片；GPT另一次请求可以成功。

**处理**：解析HTTP、业务状态和实际产物三层；业务失败终止busy、展示可读错误和任务关联信息。601的具体原因尚未确认，不把它改写成“授权过期”或模型成功。也不能因另一个模型成功就勾掉该模型的验收。

授权另按官方就绪状态及username/issuer/audience/有效期校验；MA身份、Appwrite会话、生图目标域凭据不能混用。本地固定设备用户仅用于明确的单用户开发profile，正式宿主注入已验证请求用户。日志保留错误码/任务关联而不打印token。没有用户明确的新生成意图时，不切模型、不自动重复付费调用。

**验收**：[错误映射测试](../../../../apps/server/tests/image-adapter-errors.test.ts)及 [实际失败记录](../../../../docs/verification/cloud-image-performance/README.md)。当前601仍开放，后续开发者须继续从供应商响应和授权状态取证，不照抄一个未经证实的结论。

## 案例8：CLI动作写好了，还要验证安装交付和回执持久范围

**现场**：最初已有image.attach/replace等画布动作和通用HTTP客户端，但缺完整图片配置/生成动作；能运行源码不等于MA执行环境能安装和发现。

**处理**：

- 图片仓提供纯manifest、严格schema；宿主注入权限、云端存储与媒体执行器。CLI调用同一服务，不直接修改私有draft字段。
- 配置动作保存而不调用模型；生成动作显式执行。状态、重新生成、取消的语义与错误路径分别声明。命令、input wrapper、版本参数按当前App schema发现，不把其他App版本字段套过来。
- 同key同action/input返回原回执，同key换内容拒绝。云端图片动作回执禁止普通画布PATCH伪造/删除；持久回执与执行器本地任务日志是不同恢复层，后者缺失不授权再扣费重跑。
- 当前图片工作区回执上限256，达到上限拒绝新动作；没有静默清理去重记录。此方案不是已完成的长期生产归档。
- 编译并pack，在隔离消费者安装tarball后运行真实CLI：发现→读版本→configure→同key重放→再读回。用实际安装包证明可交付，而非只运行服务端源码入口。

**验收**：未知字段、路径越界、过期版本、跨项目任务取消、App禁用、回执篡改、多张和部分失败等见 [image-app测试](../../../../apps/server/tests/image-app.test.ts)；实际安装消费者与单次GPT见 [CLI证据](../../../../docs/verification/image-cli-20261021/README.md)。多张/取消的fixture通过不等于已在真实供应商逐项验收；CLI安装也不等于MA已获得工具权限。

## 案例9：Appwrite保存成功，不等于运行服务已经全部上云

**架构边界**：Appwrite 持久化、业务后端部署与宿主组件安装是三个独立环节。仅完成存储配置，不能省略业务服务。

**服务拓扑**：画布 Web、画布 API 和图片执行适配器分别承担 UI、业务授权/持久化与模型执行，调用云端存储和模型平台；npm 包交付组件及适配代码。部署清单须列出服务地址、运行责任与网络要求，开发端口不构成生产合同。

**交接**：记录服务拓扑、运行位置、启动责任、配置来源和实际授权profile。部署后用户无需在个人电脑起服务，但平台仍须运行服务，并接入真实DA/MA身份、资源权限、生图委托与用量。不能把开发者单用户授权搬到共享服务，也不能用客户端自报用户取代校验。

**验收**：远端网络可达、已发布组件与服务版本匹配、实际用户授权、重启恢复、隔离拒绝及真实业务结果分别记录。数据云端化、后端云部署、应用登记、真实Agent调用、staging是不同出口。参考手册§9/§11；本轮没有这些线上通过证据。

## 案例10：宿主构建缺包，不能只在组件源码中找原因

**现场**：接入早期用户看到Next构建 `Can't resolve '@canvas-workspace/canvas-surface'`；后续装包又遇到其他并行App的vendor产物尚未到位。另一次公司npm登录停在浏览器授权，页面返回“需要登录”的JSON。

**排查与处理**：

- 构建报错给出的包名与import链只是定位入口，不足以确认唯一根因。检查实际服务使用哪个checkout、分支、package.json与锁文件，目标依赖是否安装，exports及CSS路径是否确实包含在tarball，是否先构建了dist。源码目录存在不代表宿主可解析包。
- 在真实消费者中安装打包产物，再验证模块解析、样式和运行。局部源码编译、打包列表、消费者安装、宿主运行分别记录；本机绝对源码路径和checkout软链不能充当交付修复。
- `npm login`等待浏览器授权及“需要登录”的JSON不能当成登录成功；官方SSO流程完成后另查registry身份/访问权限，再按发布任务上传、查询已发布版本、从registry安装复验。不要把登录ticket、token或cookie复制进案例、README或日志。此处记录登录现象，不推定其最终成功或唯一原因。
- 其他App缺少tarball导致全仓install失败时，记录缺失依赖与归属，等实际产物或在显式隔离消费者验证自己的包；不要修改他人宿主适配、伪造空包、回滚他人dirty改动来让安装变绿。
- 共享Web/API进程可能被并行任务使用。重启前核对端口、进程参数、运行配置和数据根；不能为本任务恢复旧本地存储或切换他人的云端profile。根检查失败时保留具体错误和通过范围，不能把包级通过说成全仓通过。

**验收边界**：最初模块解析错误和登录JSON是用户提供的现场信息，本文不补造单一根因。当前图片0.3.0和CLI0.1.2的实际tarball/隔离安装验证见 [CLI证据](../../../../docs/verification/image-cli-20261021/README.md)；这两个新增版本本轮没有registry发布证据，不能用以前其他包的发布结果替代。

## 给下一位开发者的最小复核表

按涉及范围选择，不要求为一次文档更新重跑所有工程测试：

- **组件交付**：实际tarball安装→完整画布渲染→保存/刷新读回；记录包版本及未实现入口。
- **异步执行**：保存前失败/保存后提交失败/真实受理/模型失败/交付pending或失败/取消和迟到结果，不能只有happy path。
- **数据恢复**：用户草稿与云端冲突先保留证据；按明确选择和版本条件恢复，不擅自复活已删除布局。
- **资源性能**：从Web真实入口测字节和尺寸；冷/热、权限失败和高倍率原件分别验，资源列表与拖拽也分别验。
- **CLI/Agent**：已安装产物的实际命令、稳定请求key、回执、权威读回与同实例UI；缺哪一层就写哪一层未验。
- **状态交接**：README写当前版本/进度/待办，合同写责任与协议，verification写当次证据；代码已改、本地已pack、npm已发布、Git已推、云端已部署不能合并写“完成”。

## 0.8.0 MVP CLI/API补齐（2026-10-22）

新增crop/adjust/transform仍复用image.tool与同一回执交付；调色复用共享像素算法，不建立第二套近似实现。样机工程通过image.edit.save/read保存稳定项目路径并恢复贴图；JSON工具产物必须在宿主真正注入CloudToolArtifactFiles，并提供同项目授权的读口，不能只证明底座可写。

两个实际验收坑：上传路径不一定等于挂卡后的canonical path，工程basePath必须用image.edit.read/state返回的实际路径；显式developmentActor会覆盖浏览器自报身份，跨租户测试需要第二个可信测试actor，不能修改x-team-id后便声称已测真实MA。

自动工程保存不能挤占256条生图去重回执额度；当前先归档已完成工程回执再从画布索引移除，旧键必须仍可查询、重放且不覆盖最新工程。真实云端与界面证据见图片仓docs/verification/mvp-api-20261022；执行与未完成边界见docs/MVP_API.md。正式MA/staging/生产隔离仍独立验收。

## 案例11：独立后端已实现，不等于正式接入完成（2026-10-23）

**现场**：生图后端长期由画布承载，“画布上能生图”曾被当成“生图后端已完成”；独立后端落地后，又容易把“镜像能构建、compose 能校验”当成“已部署、已接入宿主”。

**处理与边界**：

- 生图仓交付独立业务后端与部署制品：常驻服务入口（`Dockerfile.backend`、`deployment/compose.backend.yml`、`backend.env.example`、`deployment/README.zh-CN.md`）、独立库 `image_app_dev/app_runtime_state` 与私有桶 `image_assets_v2`、逐文件只读密钥/授权/适配挂载、单写者启停。合同见生图仓 `docs/INDEPENDENT_BACKEND.md`。
- 画布经 `CANVAS_IMAGE_APP_ORIGIN`、`CANVAS_IMAGE_APPLICATION_ID` 与 `CANVAS_TRUSTED_APP_ORIGINS` 精确白名单接入；只保存布局、完整目标作用域、工作区/资产/哈希/尺寸引用、自身投递回执和经认证的预览代理，不复制生图字节、配置、任务或编辑工程。生产 origin 必须是画布容器可达的 HTTPS 网关地址，服务间 HTTP 仅非生产 loopback 可用。
- 生产模型身份按逐已验证调用者从可信服务端适配模块取凭据；CPU/矢量部署可显式 `IMAGE_MODELS=disabled` 并省略模型适配挂载。真实用户设备授权只用于显式本地维护测试，不是生产凭据。
- 当次证据：两个真实模型、普通模型编辑工具、云端 CPU/矢量结果、浏览器生成与旋转恢复、已安装组件投递到真实画布、Devin 使用已安装 CLI 读写与跨 App 引用下载，均独立回读结果；Linux amd64 容器还实测编译后的 VTracer Worker。逐项证据及初次失败保留在 [独立生图交付验收](../../../../docs/verification/independent-image-release-20261023/README.md)，协议 fixture 与实际供应商、开发云与生产环境明确区分。
- 外部输入：正式 MA 登记、HTTPS 网关、运行时凭据、逐调用者模型 broker 与 MA Agent 工具桥仍须由负责人提供并正式验收。外部 Devin 使用 CLI 的真实证据不证明 MA 执行环境已安装和发现工具；页面规则预读取也不证明 Agent 自主调用。任一单项不得累计为四 App 正式 MA 或生产通过。
- 补充门禁：原件、多分块大文件和实际工具输出分别实测；本次确认企业 Appwrite 的分块合同为每块 5,000,000 字节，5MiB 会使特定 PNG 在末块失败；完整 multipart 又受独立网关大小限制，不能由小文件成功推断全部容量。按精确分块复验了原件字节、30MB 边界与超限拒绝，没有降低业务容量或引入存储格式迁移。扩图边缘修正另经像素与实际图像复核确认。Worker 路径必须来自可交付的编译制品，源码调试入口缺少 Worker 时明确失败；前端 DTO 的声明闭包不得依赖服务端存储实现或 Node 专属类型。

**验收**：独立业务闭环、资源私有、容器形态、画布引用接缝与模型执行分别留证；剩余宿主侧输入逐项保留待验，不用 fixture、协议桩或构建成功冒充正式接入。
